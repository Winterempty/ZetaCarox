# ZetaCaros 2.0 — วิธีเปิดบน Windows

เว็บจัดการสต็อกและยอดขายสำหรับร้านค้าขนาดเล็ก ใช้ Node.js 24 LTS และ SQLite ในเครื่อง ไม่มีค่าบริการฐานข้อมูล และไม่ต้องใช้ Docker

## เริ่มใช้ครั้งแรก

1. ติดตั้ง **Node.js รุ่น 24 LTS** สำหรับ Windows จาก https://nodejs.org/en/download เลือกรุ่น 24 โดยตรง ไม่ใช่รุ่น Current แล้วเปิดหน้าต่างคำสั่งใหม่หากเคยเปิดไว้
2. คลิกขวา ZIP ที่ได้รับ → **Extract All / แยกทั้งหมด** ไปยังโฟลเดอร์ใหม่ เช่น `C:\ZetaCaros-2` อย่าเปิดโปรแกรมจากภายใน ZIP และอย่าแตกทับโฟลเดอร์ร้านเดิม
3. เข้าโฟลเดอร์ `ZetaCaros` แล้วดับเบิลคลิก **START-WINDOWS.cmd** ไม่ต้องรัน `npm install` เพื่อใช้งานปกติ
4. เมื่อเห็น `ZetaCaros ready: http://localhost:3000` ให้เปิดที่อยู่นี้ใน Edge หรือ Chrome เก็บหน้าต่างเซิร์ฟเวอร์ไว้ตลอดการใช้งาน
5. ครั้งแรกหน้าต่างเซิร์ฟเวอร์จะแสดง `First-run setup code:` คัดลอกรหัสนี้ลงในช่อง Setup code ตั้งชื่อผู้ใช้และรหัสผ่านอย่างน้อย 12 ตัวอักษร ไม่มีบัญชีหรือรหัสผ่านเริ่มต้นที่ใช้ร่วมกัน
6. ระบบเริ่มเป็นภาษาอังกฤษ กด **ไทย** ด้านบนเพื่อเปลี่ยนภาษา ระบบจะจำภาษาบนเบราว์เซอร์นั้น ไปที่ Settings / ตั้งค่า เพื่อเปลี่ยนชื่อร้าน สกุลเงิน และเขตเวลา โดยค่าเริ่มต้นเป็น THB และ Asia/Bangkok

ข้อมูลใหม่เริ่มว่าง ไม่มีสินค้าและยอดขายทดลองแทรกในร้าน ราคาต่าง ๆ ใช้สกุลเงินร้าน ระบบจะล็อกการเปลี่ยนสกุลเงินเมื่อมีสินค้าหรือรายการทางการเงินแล้ว

หากต้องการเปิดจาก PowerShell ในโฟลเดอร์ `ZetaCaros`:

```powershell
node --version
npm start
```

ผล `node --version` ควรเริ่มด้วย `v24.` ในการตรวจรับรุ่นนี้ใช้ Node.js **24.21.0** บน Windows

## วิธีทำงานประจำวัน

- **Products / สินค้า:** เพิ่มสินค้า กรอกชื่อ SKU ราคาขาย ต้นทุน จำนวนตั้งต้น และจุดเตือน บาร์โค้ดไม่บังคับ SKU ต้องไม่ซ้ำ
- **Low stock / สินค้าใกล้หมด:** สีเหลืองเมื่อจำนวนมากกว่า 0 แต่ไม่เกินจุดเตือน
- **Out of stock / สินค้าหมด:** สีแดงเมื่อจำนวนเป็น 0 ทุกสถานะมีข้อความกำกับ
- **Stock / ปรับสต็อก:** เลือกรับเข้าหรือนำออก ระบุจำนวนและเหตุผล หน้าถัดไปแสดงจำนวนก่อนและหลัง กด Confirm & save / ยืนยันและบันทึกจึงจะเปลี่ยนจำนวน
- **Sales / ยอดขาย:** เลือกสินค้า จำนวน และวันที่ ระบบใช้ราคาขายปัจจุบัน แสดงยอดรวมให้ยืนยัน แล้วบันทึกการขายพร้อมตัดสต็อกในครั้งเดียว ไม่อนุญาตให้ขายเกินจำนวนคงเหลือ
- **History / ประวัติ:** ตรวจย้อนหลังได้ทุกการเคลื่อนไหว แบ่งหน้าละ 50 รายการ และส่งออกประวัติทั้งหมดได้
- **Archive / เก็บถาวร:** ซ่อนสินค้าจากรายการใช้งานโดยเก็บข้อมูลและประวัติไว้ เจ้าของร้านสามารถนำกลับมาใช้งานได้ ไม่มีการลบสินค้าออกจากฐานข้อมูล

กราฟใช้ช่วง 7 หรือ 30 วันล่าสุดรวมวันนี้ เทียบกับช่วงก่อนหน้าที่มีจำนวนวันเท่ากัน ตามเขตเวลาร้าน ข้อมูลมาจากการขายโดยตรงในรุ่นนี้ รวมกับยอดก่อนภาษีของใบแจ้งหนี้เดิมที่ไม่ยกเลิก วันที่ไม่มียอดใช้ค่า 0 หากช่วงก่อนหน้าเป็น 0 จะแสดงว่าเริ่มมียอดขายโดยไม่สร้างเปอร์เซ็นต์ที่คำนวณไม่ได้ **กราฟนี้คือมูลค่าการขาย ไม่ใช่เงินรับจริงหรือกำไร** การนำสินค้าออกทั่วไปจะไม่ถูกนับเป็นยอดขาย

การขายโดยตรงในรุ่นนี้เป็นรายการยืนยันแล้ว ไม่มีการแก้ไขยอดขายย้อนหลังผ่านหน้าจอ หากต้องการระบบคืนสินค้า/ยกเลิกการขาย ควรเพิ่มขั้นตอนดังกล่าวก่อนใช้งานรูปแบบที่ต้องมีการคืนสินค้าเป็นประจำ ไม่ควรใช้การเพิ่มสต็อกแทนการแก้ยอดขาย เพราะกราฟยอดขายจะไม่เปลี่ยนตาม

## นำเข้า CSV จาก Excel

1. ไปที่ Products → Import CSV → Download template หรือใช้ `samples/products-template.csv`
2. ตั้งคอลัมน์ **sku และ barcode เป็น Text / ข้อความใน Excel** ก่อนกรอก เพื่อคงเลขศูนย์ด้านหน้า การเปลี่ยนรูปแบบภายหลังไม่สามารถคืนเลขศูนย์ที่ Excel ตัดไปแล้วได้
3. หัวตารางที่ต้องมีคือ `sku,name,price,cost,stock,reorder` และเพิ่ม `barcode` ได้ ไฟล์ตัวอย่างมีครบทั้ง 7 คอลัมน์ รองรับหัวภาษาไทย: รหัสสินค้า, ชื่อสินค้า, ราคาขาย, ต้นทุน, จำนวนคงเหลือ, จุดเตือน, บาร์โค้ด
4. ราคาและต้นทุนใช้หน่วยสกุลเงินร้าน เช่น `35.50` ไม่ใช้หน่วยสตางค์ ไม่ใส่เครื่องหมายสกุลเงินหรือเครื่องหมายคั่นหลักพัน จำนวนและจุดเตือนต้องเป็นจำนวนเต็ม 0–1,000,000
5. บันทึกเป็น **CSV UTF-8 (Comma delimited)** รองรับตัวคั่นจุลภาค อัฒภาค และแท็บ ขนาดไม่เกิน 256 KB และไม่เกิน 500 รายการต่อไฟล์
6. เลือกไฟล์ ระบบแสดงทุกแถว พร้อมราคา ต้นทุน จำนวน จุดเตือน และบาร์โค้ด หากมีข้อผิดพลาดจะแสดงเหตุผลในแถวนั้น และไม่บันทึกทั้งไฟล์
7. ตรวจตัวอย่างแล้วกด **Confirm import / ยืนยันนำเข้า** หากมีผู้อื่นเปลี่ยนข้อมูลสินค้าหลังดูตัวอย่าง ระบบจะให้ตรวจตัวอย่างใหม่ก่อน

**การนำเข้าเพิ่มสินค้าใหม่เท่านั้น** หาก SKU มีอยู่แล้วจะปฏิเสธ เพื่อไม่เขียนทับสต็อกเดิม ใช้ Edit / แก้ไข หรือ Stock / ปรับสต็อกสำหรับสินค้าเดิม การส่งออกแล้วนำกลับเข้าร้านเดิมจึงไม่ใช่วิธีอัปเดตสินค้าเป็นชุด

ไฟล์ CSV ที่ส่งออกเป็น UTF-8 พร้อม BOM สำหรับ Excel ฟิลด์ข้อความที่อาจถูก Excel มองเป็นสูตรจะมีเครื่องหมาย `'` นำหน้าเพื่อให้เป็นข้อความ ไม่ใช่สูตร ข้อมูลในฐานข้อมูลไม่ถูกแก้ไข ไฟล์ CSV เป็นรายงาน ไม่ใช่ข้อมูลสำรองครบระบบ

## สแกนบาร์โค้ด

- ไปที่ Scan / สแกน แล้วกด Start camera / เปิดกล้อง อนุญาตใช้กล้องเมื่อเบราว์เซอร์ถาม การประมวลผลภาพอยู่ในเบราว์เซอร์ ไม่มีการอัปโหลดภาพกล้องไปยังบริการอื่น
- รองรับบาร์โค้ดมาตรฐานผ่าน ZXing ที่บรรจุมาพร้อมโปรแกรม เช่น EAN-13, UPC และ Code 128 ไม่ต้องดาวน์โหลดตัวอ่านจาก CDN ขณะใช้งาน
- มีบาร์โค้ด EAN-13 ทดลอง **8851234567898** บนหน้าสแกน และไฟล์ `samples/sample-barcode.svg` พิมพ์หรือเปิดบนอุปกรณ์อีกเครื่องเพื่อส่องกล้องได้
- ปุ่มทดลองค้นหาไม่สร้างสินค้าและไม่ปรับจำนวน หากต้องการให้ค้นหาพบ ให้กำหนดรหัสนี้กับสินค้าทดลอง หรือนำเข้าไฟล์ตัวอย่างโดยตั้งใจ
- กรอกบาร์โค้ดหรือ SKU เองได้ตลอด เมื่อค้นพบสินค้า จะต้องเลือกทำรายการและยืนยันก่อนเปลี่ยนจำนวน
- หากไม่เห็นภาพ ให้ตรวจสิทธิ์กล้องในเบราว์เซอร์ ปิดแอปอื่นที่ใช้กล้อง และลองกรอกรหัสเอง กล้องจะหยุดเมื่อออกจากหน้า ซ่อนแท็บ หรือค้นพบสินค้า

## เปิดจากมือถือ

การจัดหน้าเหมาะกับมือถือ แต่ `localhost` บนมือถือหมายถึงมือถือเอง ไม่ใช่คอมพิวเตอร์ร้าน ค่าเริ่มต้นของระบบเปิดเฉพาะบนเครื่อง Windows เพื่อไม่เปิดข้อมูลร้านออกเครือข่ายโดยไม่ตั้งใจ

การใช้มือถือร่วมกับคอมพิวเตอร์ร้านต้องมี **HTTPS reverse proxy พร้อมใบรับรองที่มือถือเชื่อถือ** และตั้งค่า `PUBLIC_ORIGIN` ให้ตรงกับ URL จริง ให้ผู้ดูแลเครือข่ายจัดเตรียมส่วนนี้ก่อน แล้วเปิดด้วยตัวอย่างต่อไปนี้ (เปลี่ยน URL เป็นของร้านจริง):

```powershell
$env:PUBLIC_ORIGIN = "https://stock.your-shop.example"
npm start
```

ให้ reverse proxy ส่งไปยัง `http://127.0.0.1:3000` และส่ง Host เดิม อย่าเปิดพอร์ต 3000 สู่ภายนอกโดยตรง ไม่ต้องตั้ง `HOST=0.0.0.0` หาก proxy อยู่เครื่องเดียวกัน ถ้า proxy อยู่คนละเครื่องจึงค่อยกำหนด HOST และจำกัด firewall ให้เข้าถึงจาก proxy เท่านั้น การเชื่อมผ่าน `http://192.168...` อย่างเดียวใช้กล้องมือถือไม่ได้

ชุดนี้ไม่ได้ติดตั้ง reverse proxy หรือใบรับรองให้ และไม่ได้ทดสอบกล้องของมือถือจริง การทดสอบครอบคลุมเบราว์เซอร์ Edge, ขนาดหน้าจอ 390/768/1440 px และการอ่านวิดีโอจำลองผ่านตัวอ่านจริง

## สำรองและกู้คืนข้อมูล

ข้อมูลอยู่ที่ `data/business.sqlite` พร้อมไฟล์ SQLite `-wal` / `-shm` ขณะเปิดระบบ อย่าคัดลอกเฉพาะไฟล์ฐานข้อมูลขณะโปรแกรมกำลังทำงาน ให้ใช้ปุ่มสำรองแทน

**สำรองระหว่างใช้งาน:** เจ้าของร้านไปที่ Settings → Download backup ไฟล์ `.sqlite` ที่ดาวน์โหลดรวมสินค้า ยอดขาย ผู้ใช้ และรายการเดิมทั้งหมด ระบบเก็บสำเนาเพิ่มใน `data/backups` ด้วย ควรเก็บไฟล์สำรองอีกชุดไว้นอกเครื่องและจำกัดผู้เข้าถึง เพราะมีข้อมูลร้านและรหัสผ่านที่แฮชไว้

**สำรองผ่านคำสั่ง:** ปิดเซิร์ฟเวอร์ด้วย Ctrl+C ก่อน แล้วเปิด PowerShell ที่โฟลเดอร์โปรแกรม:

```powershell
npm run backup
```

**กู้คืน:** ปิดเซิร์ฟเวอร์ก่อน และตรวจให้แน่ใจว่าเลือกไฟล์ที่ต้องการกู้คืน เพราะข้อมูลปัจจุบันจะถูกแทนที่ ตัวอย่าง:

```powershell
npm run restore -- "D:\Shop backups\business-2026-09-14.sqlite" --confirm
npm start
```

ระบบตรวจความสมบูรณ์ของไฟล์ก่อนกู้คืน เก็บฐานข้อมูลปัจจุบันเป็น `business.sqlite.before-restore-...` และยกเลิกเซสชันเดิมทั้งหมด คุณต้องเข้าสู่ระบบด้วยบัญชีที่อยู่ในไฟล์สำรอง รองรับข้อมูลสำรอง schema 1 และ 2

## ย้ายจาก ZetaCaros 1.2 โดยเก็บข้อมูลเดิม

ต้นฉบับ ZIP ที่แนบมาถูกเก็บไว้ครบใน `original/ZetaCaros-01-business-v1.2.zip` ภายในต้นฉบับนี้ไม่พบไฟล์ฐานข้อมูลร้าน จึงไม่มีข้อมูลร้านจริงที่ถูกนำมาทดสอบหรือแก้ไข

1. เปิดระบบรุ่นเดิม แล้วดาวน์โหลดข้อมูลสำรอง `.sqlite` จาก Settings เก็บไฟล์นี้ไว้ต่างหาก **อย่าแตก ZIP รุ่นใหม่ทับโฟลเดอร์เดิม**
2. ปิดเซิร์ฟเวอร์เดิม แตก ZIP รุ่นใหม่ไปโฟลเดอร์ใหม่
3. เปิด PowerShell ในโฟลเดอร์ `ZetaCaros` รุ่นใหม่ แล้วใช้ `npm run restore -- "เส้นทางไฟล์สำรองเดิม.sqlite" --confirm`
4. เริ่มรุ่นใหม่ด้วย `START-WINDOWS.cmd` เข้าระบบด้วยชื่อผู้ใช้และรหัสผ่านเดิม ไม่มีการสร้างบัญชีใหม่ทับบัญชีเดิม
5. ระบบอัปเกรด schema 1 → 2 โดยเพิ่มช่องบาร์โค้ดและตารางยอดขาย ไม่เปลี่ยนหรือลบรายการเดิม และสร้าง `business.sqlite.before-v2-...sqlite` ก่อนอัปเกรด
6. ตรวจจำนวนสินค้า ผู้ใช้ และประวัติ แล้วสร้างข้อมูลสำรองรุ่นใหม่อีกครั้ง

ใบแจ้งหนี้ การซื้อ ผู้ติดต่อ ค่าใช้จ่าย และการจัดการผู้ใช้เปิดผ่าน Settings → Open legacy workspace หรือ `/legacy` รหัสผ่านและสิทธิ์เดิมยังใช้ได้ หน้า Reports เดิมยังเป็นรายงานธุรกิจเดิม; รายงานการขายโดยตรงของรุ่น 2 อยู่ใน Sales และกราฟใหม่รวมใบแจ้งหนี้เดิมตามคำอธิบายข้างต้น

อย่านำฐานข้อมูลที่อัปเกรดเป็น schema 2 ไปเปิดด้วยโปรแกรม 1.2 หากต้องย้อนกลับ ให้ใช้โฟลเดอร์ต้นฉบับและข้อมูลสำรอง schema 1 ที่เก็บไว้ การย้อนกลับจะไม่มีรายการใหม่ที่เกิดขึ้นหลังอัปเกรด

## หากเปิดไม่ได้

- **ไม่พบ node / รุ่นไม่ใช่ 24:** ติดตั้ง Node.js 24 LTS แล้วปิด–เปิดหน้าต่างคำสั่งใหม่
- **พอร์ต 3000 ถูกใช้งาน:** ปิด ZetaCaros อีกหน้าต่าง หรือใช้ `$env:PORT="3001"; npm start` แล้วเปิด `http://localhost:3001`
- **Database is in use:** ตรวจว่าเซิร์ฟเวอร์ยังทำงานอยู่หรือไม่ หากเครื่องดับแล้วมีไฟล์ `.lock` ค้าง ให้ตรวจใน Task Manager ว่าไม่มี ZetaCaros ใช้ฐานข้อมูลนี้อยู่ก่อน จึงค่อยเปลี่ยนชื่อไฟล์ `data/business.sqlite.lock` เป็น `.lock.old` แล้วเปิดใหม่ ห้ามเปลี่ยนชื่อไฟล์ฐานข้อมูล `.sqlite` แทน
- **รหัสตั้งค่าไม่ถูก:** ใช้รหัสจากหน้าต่างเซิร์ฟเวอร์ที่กำลังทำงานอยู่ รหัสตั้งค่าจะเปลี่ยนเมื่อเริ่มเซิร์ฟเวอร์ใหม่ก่อนสร้างบัญชีสำเร็จ
- **ข้อมูลเปลี่ยนระหว่างทำรายการ:** เปิดหน้าอีกครั้ง ตรวจจำนวนล่าสุด แล้วยืนยันใหม่ ระบบป้องกันการเขียนทับข้อมูลที่เปลี่ยนจากอีกแท็บหรืออีกผู้ใช้
- **CSV ภาษาไทยอ่านไม่ได้:** บันทึกจาก Excel เป็น CSV UTF-8 ไม่ใช่ CSV แบบ ANSI หรือ UTF-16
- **ลืมรหัสผ่าน:** ให้ผู้ดูแลอีกบัญชีรีเซ็ตผ่านหน้าระบบเดิม ไม่มีช่องทางข้ามรหัสผ่านหรือบัญชีลับ

## สำหรับผู้พัฒนา

```powershell
npm test
# เฉพาะการทดสอบเบราว์เซอร์และหน้าจอเดิม ต้องติดตั้ง dev dependencies:
npm ci
npm run test:ui
npm run test:legacy-ui
```

`npm test` ไม่ต้องติดตั้งแพ็กเกจเสริม บน Windows การทดสอบเบราว์เซอร์ใช้ Microsoft Edge ที่ติดตั้งอยู่ บนระบบอื่นให้ติดตั้ง Chromium ของ Playwright ด้วย `npx playwright install chromium` ก่อน การทดสอบใช้ฐานข้อมูลชั่วคราวแยกจากข้อมูลร้าน
